# Долголетие

Личное приложение для наблюдения за показателями здоровья. Оно читает данные из закрытого репозитория, считает статусы по фиксированным порогам из каталога и показывает их на телефоне. Сервера нет. В этом репозитории нет персональных данных: только код.

## Устройство

- `index.html`, `styles.css` — оболочка и оформление.
- `src/main.js` — запуск, маршруты, экран настроек.
- `src/engine.js` — чистые функции: разбор JSONL, статусы, производные показатели, модель для экранов.
- `src/data.js` — настройки и кэш в `localStorage`, загрузка данных через GitHub API.
- `src/views.js`, `src/charts.js`, `src/dom.js` — экраны, графики, сборка DOM без `innerHTML`.
- `sw.js` — service worker: оболочка работает без сети.
- `manifest.webmanifest`, `icons/` — установка на домашний экран.
- `tests/` — тесты на `node:test`.
- `docs/ARCHITECTURE.md` — контракты данных и кода.
- `docs/ROADMAP.md` — состояние проекта, принятые решения, план развития.
- `tools/acceptance.py` — приёмка интерфейса: снимки экранов и проверка интерактива.
- `.nojekyll` — GitHub Pages отдаёт файлы как есть.

## Первый запуск

1. Включите GitHub Pages: Settings → Pages → Deploy from a branch → ветка `main`, папка `/ (root)`.
2. Создайте fine-grained personal access token (Settings → Developer settings → Personal access tokens → Fine-grained tokens). Ограничьте его одним закрытым репозиторием с данными, право: Contents: Read-only.
3. Откройте сайт на телефоне. На экране «Настройки» вставьте имя репозитория (`владелец/репозиторий`) и токен, нажмите загрузку.
4. В Safari: «Поделиться» → «На экран Домой».

## Токен

- Токен даёт только чтение содержимого одного репозитория. Записать, удалить или изменить что-либо он не может, к другим репозиториям доступа у него нет.
- Хранится в `localStorage` браузера на этом устройстве. Отправляется только на `https://api.github.com`, в адреса и логи не попадает.
- Кто получит доступ к разблокированному устройству и браузеру, сможет его прочитать. Поэтому токен только на чтение и на один репозиторий.
- Отзыв: GitHub → Settings → Developer settings → Fine-grained tokens → Delete. На устройстве: «Настройки» → «Удалить данные с этого устройства» (стирает токен и кэш).

## Гостевой доступ

Врачу или нутрициологу можно дать ссылку только для просмотра. Гостю не нужен ни аккаунт GitHub, ни токен.

- Ссылку создаёт и отзывает куратор в закрытом репозитории данных. Для каждого получателя своя ссылка и свой срок.
- Данные для гостя — отдельный зашифрованный снимок в публичном репозитории `longevity-share`. Ключ находится только в самой ссылке, после знака `#`, и на сервер не отправляется.
- В снимок не входят исходные бланки, номера заказов и рабочие заметки.
- Отзыв удаляет снимок. Уже открытые данные гость мог сохранить: отзыв этого не отменяет.

Чтобы это работало, репозиторий `longevity-share` должен быть публичным, с включённым GitHub Pages (ветка `main`, корень).

## Разработка

```
cd <родитель обоих клонов> && python3 -m http.server 8765
open http://localhost:8765/longevity-app/?base=/longevity-data
node --test                 # в longevity-app
node tools/validate.mjs     # в longevity-data
```

Параметр `?base=` включает локальный режим: файлы читаются с того же origin, настройки и кэш не используются.
