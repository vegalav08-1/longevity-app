# Состояние проекта и план развития

Обновлено: 2026-11-15. Документ для владельца и для любого агента, который продолжает
работу без истории чата. Контракты данных и кода — в [ARCHITECTURE.md](ARCHITECTURE.md).
Персональных данных здесь нет и быть не должно.

## Что это

Личное приложение долголетия: показатели здоровья во времени, их статусы, связи между
ними и план того, что измерить дальше. Работает на телефоне как веб-приложение, без сервера.

- `longevity-app` — публичный репозиторий, только код. Отдаётся через GitHub Pages.
- `longevity-data` — приватный репозиторий: профиль, каталог показателей, измерения,
  исходные документы, комментарии, план, заметки куратора.

## Роли

- **Владелец** присылает данные в чат: числа, PDF, фото, скриншоты.
- **Куратор** — чат с доступом к `longevity-data`. Проверяет данные, записывает их,
  обновляет комментарии и план, отвечает владельцу. Протокол: `AGENTS.md` в `longevity-data`.
  Контекст вне цифр куратор хранит в `notes/` того же репозитория.
- **Архитектор** — модель, которая ведёт проект: контракт, дизайн интерфейса, тексты
  комментариев, приёмка. Рутинную реализацию отдаёт субагентам меньшей модели, результат
  проверяет сам и сам делает коммит.
- **Приложение** только читает. Токен на устройстве даёт право «Contents: Read-only»
  на один репозиторий.

## Принятые решения и их причины

| Решение | Причина |
|---|---|
| Два репозитория: код публичный, данные приватные | GitHub Pages на бесплатном тарифе публикует только публичный репозиторий; медицинские данные публиковать нельзя |
| Без сервера, данные читаются из браузера через GitHub API | Нет расходов, нет стороннего хранилища с медицинскими данными |
| Токен только на чтение, хранится в `localStorage` | Утечка токена с устройства не даёт изменить или удалить данные |
| Без зависимостей и сборки, строгая CSP, без `innerHTML` | Нечему устаревать, нет стороннего кода рядом с медицинскими данными |
| Модель не работает в момент показа | Статусы считаются по фиксированным порогам, результат воспроизводим и не зависит от сети |
| Комментарии и план пишет модель при внесении данных, в `commentary.json` и `plan.json` | Толкование «как в чате» без модели на устройстве; у каждого текста есть дата и автор |
| Необязательные файлы не блокируют цифры | Ошибка в комментарии или плане не должна скрывать измерения |
| Данные вносит куратор в чате, приложение не пишет | Проверка значений человеком и моделью до записи; токену не нужно право записи |
| Значение из чата записывается с `source: "chat"` | Источник каждого числа виден: документ или слова владельца |
| Питание учитывается недельными средними | Подробный дневник бросают; для выводов достаточно калорий, белка и клетчатки за неделю |
| Два уровня порогов: референс и функциональный оптимум | Референс отделяет болезнь, оптимум — зону наименьшего долгосрочного риска. У каждого оптимума в каталоге указан источник и доказательность; без исследований с исходами оптимум не вносится |
| Только светлая тема | Требование владельца |

## Требования владельца к интерфейсу

Собраны из его замечаний, действуют для всех будущих экранов.

- Сначала телефон.
- Аккордеон: раздел → показатель → подробности. Глубина по запросу, экран не перегружен.
- У каждого показателя и каждого раздела короткое описание и комментарий по текущей ситуации.
- Блоки и группы данных акцентированы и различимы с первого взгляда.
- Шкалы и диаграммы нужны, но аккуратные: без грубых блоков.
- План со сроками; приоритет и срочность видны сразу, карточки плана не сливаются.
- Интерактивность: фильтры, раскрытие, копирование сообщения для куратора, отметка «отправлено».
- В интерфейсе видно, какие данные и когда передавать куратору.
- Разделы образа жизни наравне с анализами: питание, тренировки, сон и привычки, психика и стресс.
- Техническое соглашение: белый фон — данные, бледно-голубой — толкование модели.

## Что сделано (версия 0.1)

- Экран «Сегодня»: общий вывод, фильтр, разделы двух групп (системы организма и образ жизни),
  профиль раздела на нормированной шкале, показатели с шкалой и статусом.
- Экран показателя: значение, шкала с референсом и оптимумом, комментарий, история, зачем нужен.
- Экран «План»: счётчики, полоса дней, фильтр по приоритету, карточки с причиной, сроком,
  трудоёмкостью и готовым сообщением для куратора.
- Экран «Куратор»: что и когда присылать, расписание регулярных данных.
- Экран «Настройки»: репозиторий, токен, удаление данных с устройства.
- Производные показатели: HOMA-IR, не-ЛПВП холестерин, свободный и биодоступный тестостерон
  по Вермюлену, FIB-4.
- Работа без сети: оболочка из service worker, данные из кэша с обновлением при открытии.
- Установка на домашний экран.
- Тесты движка и слоя данных на синтетических данных; валидатор в репозитории данных.

## Известные пробелы

- Отрисовка последних версий экранов «План» и «Куратор» в Safari на iPhone проверена
  только в Chrome с шириной 390 и 320 пикселей.
- История показателя осмысленна от двух точек; пока по большинству показателей точка одна.
- Ввод данных с телефона идёт только через чат с куратором.
- Данные приложения «Здоровье» (шаги, сон) вручную, скриншотом.
- Опросники проходятся в чате, в приложении их нет.
- Отметка «отправлено куратору» хранится на устройстве и не знает, записал ли куратор данные.
- Расчёт биологического возраста (PhenoAge) не реализован: не хватает входных показателей.
- Связи между показателями показаны текстом комментариев, отдельной схемы связей нет.

## Дальше

Порядок по пользе, без дат. Каждый пункт начинается с правки контракта в `ARCHITECTURE.md`.

1. **Импорт старых анализов.** Задача куратора, кода не требует. Даёт динамику и оживляет графики истории.
2. **Опросники в приложении** (PHQ-9, GAD-7, PSS-10, STOP-BANG): подсчёт балла на устройстве
   и готовое сообщение для куратора. Запись по-прежнему через куратора.
3. **Выгрузка из «Здоровья» через «Команды»:** шаги и сон за неделю одним сообщением.
4. **PhenoAge** как производный показатель, когда в данных будут все входные анализы.
5. **Экран динамики:** сравнение двух дат, изменения со времени прошлого контроля.
6. **Схема связей** между показателями внутри раздела.
7. **Ввод с телефона без чата.** Требует токена с правом записи, это меняет модель безопасности;
   решение принимается отдельно.

## Как работать над проектом

- Сначала меняется контракт в `docs/ARCHITECTURE.md`, затем код.
- Перед каждым коммитом в `longevity-app`: `node --test` и поиск персональных данных
  в изменениях (реальные значения, даты рождения, номера заказов, имена, токены).
- Перед каждым коммитом в `longevity-data`: `node tools/validate.mjs`.
- Приёмка интерфейса: `python3 tools/acceptance.py <папка для снимков>` из корня
  `longevity-app`, рядом должен лежать клон `longevity-data`. Скрипт открывает приложение
  в локальном режиме на ширине 390 и 320 пикселей, проверяет фильтры, раскрытие, копирование,
  отсутствие горизонтальной прокрутки и ошибок в консоли, сохраняет снимки экранов.
  Снимки содержат реальные данные: в репозиторий их не добавлять.
- Локальный просмотр: раздел «Development» в `ARCHITECTURE.md`.
- Ветка `main`, публикация через GitHub Pages сразу после push.
